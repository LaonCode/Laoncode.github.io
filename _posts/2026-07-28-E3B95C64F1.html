오늘은 Bandit19 문제를 해결해보려고 한다.

이번 문제의 정보를 정리해 보면 아래와 같다.

1. 다음 레벨의 비밀번호는 home 디렉터리의 readme 파일에 저장되어 있다.
2. 누군가 .bashrc 파일을 수정하여 SSH로 로그인 시 로그아웃되도록 설정했다.

즉, Level18에 들어가기만 하면 readme파일을 찾아서 바로 풀 수 있지만 핵심은 수정된 .bashrc 파일인 듯한 문제라고 판단할 수 있다.

가장 먼저 수정된 파일인 .bashrc에 대해 알아보자.

.bashrc란 리눅스 배시(Bash) 쉘이 대화형으로 열릴 때마다 실행되는 초기 설정 파일로, 주로 단축 명령어(alias), 환경 변수, 쉘 함수를 저장하는 데 쓰 인다. 간단하게 보면 shell 중 /bin/bash라는 shell을 쓸 때 .bashrc의 스크립트가 실행되도록 하는 것이다. 예를들어서 .bashrc 스크립트에 id 라고 적어 두었다고 가정하면 이 shell을 킬 때마다 맨 상단에 id 결과값이 출력되는 것이다. 

문제에서는 이러한 .bashrc에 작성해둔 것을 누군가가 바꿔놨다고 이야기하고 있다. ssh를 통해 shell를 연결하면 기본 shell인 bash를 연결해 실행하여 우리에게 전달해 준다. 그런데 bash가 실행 될 때 수정된 파일이 실행되면서 지난 레벨에서 봤듯이 "Byebye!"하며 종료를 시켜버렸던 것이다. 그래서 기본 shell인 bash를 사용을 못하는 것이다.

문제 사이트에서는 ssh, ls, cat 명령어가 필요하다고 되어 있으니 ssh 명령어에는 정답이 있지 않을까? 생각하며 ssh -h 명령어를 통해 ssh 명령어를 다시 한번 살펴보자.

여기서 집중적으로 봐야할 것은 "destination [command [argument ...]]" 이 부분이다. command라고 적혀 있는 것을 보면 ssh를 사용할 때 뒤에 명령어를 실행할 수 있다는 것이다. 기존에 문제를 풀면서 ssh로 로그인할 때 특정 명령어를 입력하지 않고 입력하게되면 ssh를 연결하고 기본 bash shell을 연결해서 전달해주었을 것이다. 그런데 여기에 내가 원하는 명령어를 입력하게 되면 bash shell이 실행이 안되고 내가 원하는 명령어가 실행이 될 것이다. 이제 이 점을 이용해서 문제를 해결하면 될 것 같다.

먼저 bash shell에 연결하면 막히는 것을 알았으니 다른 shell인 /bin/sh에 연결해 보자. (/bin/sh 이란? 유닉스 및 리눅스 시스템에서 스크립트를 실행하는 기본 셸 프로그램이자 명령어 경로)

ssh bandit18@bandit.labs.overthewire.org -p 2220 /bin/sh를 입력하고 비밀번호를 입력하면 아무것도 뜨지 않을 것이다. 하지만 여기서 명령어를 입력하면 명령어에 맞는 결과가 나오는 것을 확인할 수 있다. 즉 현재 shell이 연결된 상태라는 것이다. 문제에서 home 디렉터리의 readme에 있다고 했으니 cat 명령어를 통해 readme파일일 읽어서 비밀번호를 획득하면 이번 문제는 끝이난다.

물론 바로 cat readme라고 명령어를 입력해도 비밀번호가 나오긴 한다.
