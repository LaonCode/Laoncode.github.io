#Git 알아보기

Git의 핵심 기능은 아래와 같다.

버전 관리(version control), 백업(backup), 협업(collaboration)

1. 버전 관리

우리는 파일을 생성하고 그 파일을 수정하면 수정본, 최종 수정본 등 추가적인 이름을 붙이게 된다. 만약 , 1000개가 넘는 문서를 수정한다면 내가 어떤 파일에서 어떤 내용을 수정했는지 기억할 수 없을 것이다. 문서를 수정할 대마다 언제, 어떤 것을 수정하고 변경했는지 등 구체적으로 기록하는 것을 '버전 관리'라고 하고 이 버전 관리를 하는 시스템이 바로 깃(Git)이다.

2. 백업

만약 중요한 자료를 컴퓨터에 저장한다고 하자. 그럼 가끔 이 자료가 어쩌다가 컴퓨터에서 삭제되면 어떡할까라는 생각을 하게 된다. 이후 우리는 자료를 컴퓨터에만 저장한다면 언젠가 그 자료가 유실될 것이라고 확신하게 된다. 그래서 반드시 백업을 해야 한다. 보통 백업을 할 때에는 USB나 구글 드라이브를 많이 사용한다. 하지만 백업 공간을 제공하는 인터넷 서비스에는 깃 파일을 위한 것도 여럿 있다. 이것을 깃의 원격 저장소 또는 온라인 저장소라고 한다. 이러한 서비스 가운데 가장 많이 쓰이는 것이 바로 깃허브(Github)이다.

3. 협업

깃허브와 같은 온라인 서비스를 사용하면 여러 사람이 함께 일할 수 있다. 예를 들어 나와 팀원 3명이 협업을 한다고 가정하였을 때, 먼저 내가 작업해서 원격 저장소에 파일을 올리면 다른 팀원1이 내려받아 작업한 뒤, 그 결과물을 다시 원격 저장소에 올려 팀원2,3이 작업하는 방식이 가능하다. 또한 누가 어느 부분을 어떻게 수정했는지 기록으로 남아서 나중에 오류가 생겼을 때도 파악하기 쉽다.

#Git 프로그램의 종류

깃허브 데스크톱

깃허브 데스크톱(GitHub Desktop)은 깃 온라인 저장소 서비스인 깃허브엣 제공하는 프로그램으로, 복잡한 깃 사용법을 그래픽 사용자 인터페이스(GUI)로 구현한 것이다.

장점 : 사용하기 쉬워서 누구나 배울 수 있다.
단점 : 기본 기능 위주이다.

토터스깃

토터스깃(TortoiseGit)은 윈도우 탐색기의 빠른 메뉴에 추가되는 윈도우 전용 프로그램이다.

관련 영상 : https://opentutorials.org/module/3994

소스트리

소스트리(SourceTree)는 깃의 기본 기능부터 고급기능까지 사용할 수 있는 프로그램이다.

관련 영상 : https://opentutorials.org/module/3802

 

#커맨드 라인 인터페이스(CLI)

커맨드 라인 인터페이스(Command Line Interface, CLI)는 터미널 창에 명령을 직접 입력해서 깃을 사용하는 방식이다.

#리눅스 명령어

터미널 창에서 깃을 사용하기 위해 쓰는 명령은 리눅스 명령과 같다. 그래서 리눅스 명령 몇 가지를 아래와 같이 정리해 보았다.

 pwd : 현재 위치의 경로 표시
ls : 현재 디렉터리에 어떤 파일이나 디렉터리가 있는지 확인

[Option]
-a : 숨긴 파일이나 디렉터리도 함께 표시
-l : 파일이나 디렉터리의 상세 정보를 함께 표시
-r : 파일의 정렬 순서를 거꾸로 표시
-t : 파일 작성 시간순(내림차순)으로 표시
clear : 터미널 창 지우기
(혹은 단축키 Shift+l)
cd : 디렉터리 이동
[리눅스에서 디렉터리를 나타내는 기호]
~ : 현재 접속 중인 사용자 디렉터리를 가리킨다.
. : 현재 사용자가 작업 중인 디렉터리
.. : 현재 디렉터리의 상위 디렉터리
mkdir [디렉터리 이름] : 현재 디렉터리 안에 하위 디렉터리를 만든다.
rm [option] [파일 혹은 디렉터리 이름] : 디렉터리 혹은 파일 삭제

[Option]
-r : 디렉터리 안에 있는 하위 디렉터리와 파일을 함께 삭제한다.
exit : 터미널 종료

#Git으로 버전 관리하기

Git 저장소 만들기

git init 명령어를 입력하여 현재 디렉터리에서 깃을 사용할 수 있도록 초기화한다. 이후 터미널에 잇는 파일 경로 끝에 (main)이라고 표시된 것을 확인할 수 있다. 또한 ls -al를 입력하여 .git 디렉터리가 생성된 것을 알 수 있다.

Git과 버전

버전이란?
프로그램 개발에서 수정 내용이 쌓이면 새로 번호를 붙여서 이전 상태와 구별한다. 이렇게 번호등을 통해 구별하는 것을 버전이라고 한다.

그렇다면 깃에서 버전이란 무엇일까. 깃에서 버전이란 문서를 수정하고 저장할 때마다 생기는 것이다. 또한 버전을 만든 시간과 수정 내용까지 기록할 수 있는 것이 바로 깃과 같은 버전 관리 시스템이다. 깃에서 버전을 관리하면 원래 파일 이름은 그대로 유지하면서 파일에서 무엇을 변경했는지를 변경 시점마다 저장할 수 있다. 또, 버전마다 작업한 내용을 확인하거나, 그 버전으로 되돌릴 수 있다.

Git의 작업 영역

Git은 크게 우리 눈에 보이는 디렉터리인 작업 트리와 . git 디렉터리 안에 숨은 파일 형태로 있는 스테이지와 저장소가 있다.

먼저 작업트리(Working tree)는 파일 수정, 저장 등의 작업을 하는 디렉터리이다. 

다음으로 스테이지(stage)는 버전으로 만들 파일이 대기하는 곳이다. 스테이징 영역(staging area)이라고도 한다. 예를 들어 작업 트리에서 파일 10개를 수정했는데 4개만 버전으로 만들려면 이 파일 4개만 스테이지로 넘겨주면 된다.

마지막으로 저장소(repository)는 스테이지에서 대기하고 있던 파일들을 버전으로 만들어 저장하는 곳이다.

그럼 이 3개의 작업영역은 어떻게 작동될까?

먼저 작업트리에서 문서를 수정한다. 그 이후 수정한 파일 가운데 버전으로 만들고 싶은 것을 스테이징 영역, 즉 스테이지에 저장한다. 그리고 스테이지에 있던 파일을 저장소로 커밋하면 버전이 만들어진다.

1. 작업 트리에서 변경 사항 만들기

이제 디렉터리에 새로운 파일을 만들고 수정해 보겠다

git status

먼저 Git 상태를 확인하기 위해 git status를 입력해 보았다.

그럼 위 사진처럼 Git의 상태를 보여주는 메시지가 나타난다. 이 메시지를 분석하면 아래와 같다.

On branch main : 현재 main 브랜치에 있다.

No commits yet : 커밋한 파일이 아직 없다.

nothing to commit (create/copy files and use "git add" to track) : 현재 커밋할 파일이 없다.

이후 비주얼 스튜디오에서 hello.txt파일을 만들어 내용을 작성해 주었다. 이후 git status 명령어를 다시 입력해 보았다. 

이전과는 달리 Untracked files라는 메시지가 추가되었다. 깃에서는 버전을 아직 한 번도 관리하지 않은 파일을 Untracked files라고 한다. 지금까지 작업트리에서 문서 파일을 만든 것이다.

2. 스테이지에 변경 사항 올리기 - git add

작업 트리에서 파일을 만들거나 수정했다면 스테이지에 추가한다. 이렇게 Git에게 버전 만들 준비를 하라고 알려 주는 것을 스테이징(staging) 또는 스테이지에 올린다라고 표현한다.

 Git에서 스테이징 할 때 사용하는 명령은 git add이다. 그리하여 아까 만든 파일을 git add 명령어를 통해 스테이징 해주었다. 이후 git status로 확인해 보니 Untracked files라는 문구가 Changes to be committed문구로 바뀐 것을 확인할 수 있었다. 또한 hello.txt 파일 앞에 "new file"이라는 수식어가 추가로 나타난다. '새 파일 hello.txt를 (앞으로) 커밋할 것이다.'라는 뜻이다. 그럼 지금까지 앞에서 만든 hello.txt 파일이 스테이지에 추가되었다. 이제 버전을 만들 준비를 마친 것이다.

3. 스테이징 한 파일 커밋하기 - git commit

파일이 스테이징 영역에 있다면 이제 버전을 만들 수 있다. 버전 만드는 것을 Git에서는 커밋(commit)한다라고 한다. 커밋할 때는 버전의 변경 사항을 확인할 수 있도록 메시지를 함께 기록해 두어야 한다.

Git에서 파일을 커밋하는 명령은 git commit이다. 그리고 한 칸 띄운 후에 -m 옵션을 붙이고 커밋과 함께 저장할 메시지를 적는다. 이 메시지를 커밋 메시지라고 한다.

git commit -m "메시지"

커밋한 후에 결과 메시지를 보면 파일 1개가 변경되었고(1 file changed), 파일에 1개의 내용이 추가되었다(1 insertion(+))고 나타난다. 스테이지에 있던 hello.txt 파일이 저장소에 추가된 것이다.

git status 명령어로 git 상태를 확인해 보면 버전으로 만들 파일이 없고(nothing to commit), 작업 트리도 수정사항 없이 깨끗하다(working tree clean)고 나타난다.

그럼 버전이 제대로 만들어졌는지는 어떻게 확인할까?

저장소에 저장된 버전을 확인할 때는 log 명령을 사용한다.

git log 명령어를 사용하면 방금 커밋한 버전을 설명하는 정보가 나타난다. 커밋을 만든 사람과 시간, 커밋 메시지가 함께 보인다. 수정한 파일을 커밋하면 이렇게; 수정과 관련된 여러 정보를 함께 저장할 수 있고 필요할 때 확인할 수도 있다. 그럼 스테이지에 있던 hello.txt 파일의 버전이 만들어졌다.

4. 스테이징과 커밋 한꺼번에 처리하기 - git commit -am

수정한 파일을 스테이지에 하나씩 올려 두었다가 한꺼번에 커밋할 수도 있지만, 수정한 내용을 스테이지에 올리는 동시에 커밋까지 처리할 수도 있다. 단, 이 방법은 한 번이라도 커밋한 적이 있는 파일을 다시 커밋할 대만 사용할 수 있다. 사용 방법은 commit 명령어에 -am 옵션을 사용하면 스테이징과 커밋을 한꺼번에 처리할 수 있다.

hello.txt파일에 "add Good bye~"라는 문구를 추가해서 테스트해 보겠다.

앞에서는 수정한 파일을 스테이지에 올리고 커밋하는 것을 git add 명령과 git commit 명령을 사용해서 처리했다. hello.txt 파일은 이전에 커밋한 적이 있으므로 git commit명령에 -am 옵션을 붙여서 스테이징과 커밋을 한꺼번에 처리할 수 있다. 위 이미지와 같이 입력하면 스테이징과 커밋 과정이 한꺼번에 보이는 것을 알 수 있다.

git log를 통해 방금 커밋한 버전에 어떤 정보가 들어 있는지 확인해 보면, hello.txt의 버전 2개가 나타나는데, 최신 버전 정보가 "add Good bye~"라는 메시지와 함께 맨 위에 보인다.

이렇게 1일차 Do it! 여름방학 모각공을 마무리한다.
