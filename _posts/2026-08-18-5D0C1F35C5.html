브랜치 만들기 - 팀원 역할

브랜치 만들기 - 팀원 역할 부분의 일부 화면이다. 팀원 역할의 앞 내용은 책을 참고하면 좋을 것 같다. 이슈 화면이 열린 상태에서 현재 이슈의 브랜치를 만들기 위해 Create a branch 링크를 클릭해 준다.

브랜치 이름을 지정하고 브랜치를 생성해 준다. 나는 plan으로 지정해 주었다. 

위와 같이 작은 창이 열리면서 원격 저장소를 페치 한 후 plan 브랜치로 전환하는 방법이 표시된다. 지금은 지역 저장소로 복제하는 방법을 사용할 것이므로 이 창은 그냥 닫아주었다.

저장소에서 작업하고 푸시하기

저장소에 자신이 작업할 브랜치까지 만들었으므로 이제 지역 저장소를 만들고 복제하겠다.

git clone [원격 저장소 주소]

VS Code를 열고 작업 중인 폴더가 있다면 폴더를 닫아준다. 이후 터미널 창을 열고 지역 저장소를 만들 위치로 이동한 후 위와 같이 입력해서 원격 저장소와 연결한다.

윈도우 탐색기를 보면 지정한 위치에 방금 복제한 저장소가 project라는 디렉터리로 만들어졌을 것이다. project 디렉터리를 작업 폴더로 추가해 준다.

git switch plan

VS Code 터미널 창에서 위와 같이 입력해서 plan 브랜치를 만든 후 전환해 주었다.

plan 브랜치가 새로 만들어지면서 원격 저장소의 plan 브랜치와 연결된다. 이것을 지역 브랜치가 원격 브랜치를 트래킹(tracking)한다고 한다.

git add plan-1.txt
git commit -m "plan-1"

간단한 기획 문서를 작성해 보겠다. project 폴더에 plan-1.txt 파일을 만들고 'plan1'이라고 작성한 후 저장해 준다. 그 이후 파일을 스테이지에 올린 후 "plan-1"이라는 메시지와 함께 커밋한다.

git push

원격 저장소로 푸시하겠다. 앞의 4번 과정에서 지역 저장소의 plan 브랜치가 원격 저장소의 plan 브랜치와 연결된 것을 확인했으므로 간단히 git push 명령으로 푸시할 수 있다. 할당받은 작업을 모두 마칠 때까지 이 과정을 반복한다.

git push -u origin [브랜치명] : 원격 저장소에 없는 브랜치로 푸시할 때 사용

풀 리퀘스트 요청하기

공동 작업에서 커밋을 푸시한 후에 꼭 해야 할 작업이 있다. 자신이 푸시한 작업을 확인하고 main 브랜치로 병합해 달라고 요청하는 것이다. 이것은 풀 리퀘스트라고 한다.

커밋을 푸시했다면 깃허브 저장소로 접속한다. 저장소의 첫 화면에는 main 브랜치가 나타나는데 앞에서 푸시한 plan-1.txt 파일이 없을 것이다. main을 클릭한 후 plan을 선택해서 plan 브랜치로 이동하겠다.

plan 브랜치에 plan-1.txt 파일이 올라와 있다. 이 파일을 풀 리퀘스트 해 보겠다. 브랜치에 새로운 커밋이 올라오면 화면 위쪽에 풀 리퀘스트 버튼이 나타난다. Compare & pull request를 클릭해 준다.

풀 리퀘스트 제목과 내용을 입력해 준다. 이때 마크다운을 사용할 수도 있고 필요하다면 이미지나 파일을 첨부할 수도 있다. 풀 리퀘스트 화면 오른쪽에 Reviewers 항목은 공동 작업자들이 내 커밋을 검토할 수 있게 지정하는 곳이다. 풀 리퀘스트 내용을 모두 작성했다면 Create pull request를 클릭해 준다.

풀 리퀘스트 화면으로 이동한다. 여기까지가 팀원으로서의 역할이다.

풀 리퀘스트 검토하고 브랜치 병합하기 - 팀장/리뷰어 역할

팀원들이 작업물을 푸시하고 풀 리퀘스트를 등록하면 팀장이나 해당 작업의 리뷰어가 작업물을 검토할 수 있다. 제대로 작업했다면 main 브랜치로 병합하고, 수정하거나 추가할 부분이 있다면 해당 내용을 기록하고 재작업하도록 할 수 있다.

다시 팀장 역할로 돌아와 보자. 공동 작업자 가운데 누군가 풀 리퀘스트를 등록했다면 검토해야 한다. 깃허브 저장소에 접속하면 화면에 Pull request 메뉴에 숫자가 보인다. 이것은 풀 리퀘스트가 몇 개인지를 나타낸다. Pull requests를 클릭하면 진행 중인 풀 리퀘스트는 Open이라 하고 처리된 풀 리퀘스트는 Closed 되었다고 한다. 기본적으로 Open 상태의 풀 리퀘스트가 표시된다. 처리할 풀 리퀘스트 제목을 클릭해 준다. 해당 화면에서는 "첫 번째 기획안"이 되겠다.

풀 리퀘스트 화면에도 여러 탭이 잇다. 처음 표시되는 Conversation 탭에는 작업자가 남긴 메시지가 나타난다. 풀 리퀘스트에 Open이라고 현재 상태가 표시된다. 만약 파일이 어떻게 바뀌었는지 확인하고 싶다면 네 번째 탭인 Files changed를 클릭해서 확인할 수 있다.

현재 커밋을 병합해도 되겠다고 생각한다면 Conversations 탭에 있는 Merge pull request를 클릭해 준다.

main 브랜치에 병합하는 커밋 메시지를 작성한다. 기본적인 커밋 제목과 내용이 나타나는데 기본 내용을 그대로 쓰거나 수정할 수 있다. Confirm merge를 클릭한다.

plan 브랜치를 만들었던 목적이 기획안을 작성하는 것이었다. 기획 작업을 마치고 main 브랜치에 병합했으므로 plan 브랜치는 더 이상 필요하지 않다. Delete branch를 클릭해서 브랜치를 삭제한다.

이제 저장소 첫 화면으로 이동해 보면 plan 브랜치에 푸시했던 plan-1.txt가 main 브랜치에 병합되어 있다.

만약 삭제한 브랜치를 되돌리고 싶다면 풀 리퀘스트 화면으로 돌아와 Restore branch를 클릭해서 되돌릴 수 있다.
