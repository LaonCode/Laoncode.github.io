# XSS란?

크로스 사이트 스크립팅(Cross-Site Scripting, XSS)은 웹 애플리케이션이 클라이언트(사용자)로부터 입력받은 신뢰할 수 없는 데이터(Untrusted Data)를 적절한 검증이나 맥락별 출력 인코딩(Context-aware Output Encoding) 없이 응답 본문이나 DOM 메타데이터에 포함할 때 발생하는 코드 주입(Code Injection) 취약점이다. 공격자는 이 취약점을 악용하여 희생자의 웹 브라우저 내에서 의도하지 않은 클라이언트 측 스크립트(주로 JavaScript)를 실행시킨다.

app.get('/search', (req, res) => {
    const query = req.query.q;
    res.send(`<h1>검색 결과: ${query}</h1>`);
});

해당 코드는 클라이언트 측(프론트엔드) 자바스크립트에서 발생하는 DOM 기반 XSS(DOM-based XSS) 취약점 예시이다.

[http://example.com/index.html#](http://example.com/index.html#)<img src=x onerror=alert(1)>

위와 같이 공격자가 # 뒤에 악성 페이로드가 포함된 URL을 피해자에게 클릭하도록 유도하면, 서버를 거치지 않고 브라우저 내부 자바스크립트가 DOM Source인 window.location.hash에서 해당 문자열을 읽어온다. 이후 이 값을 검증 없이 위험한 DOM Sink인 innerHTML에 직접 할당하게 되며, 브라우저가 이를 HTML 코드 노드로 재파싱하면서 주입된 자바스크립트가 즉시 실행된다.

 

1. 악성 페이로드 주입 (Injection)

공격자는 HTTP 요청 파라미터, Form 입력 필드, HTTP 요청 헤더, URL 경로 등을 통해 자바스크립트 실행 구문이 포함된 문자열(Payload)을 웹 애플리케이션으로 전송한다.

2. 미검증 데이터 결합 및 전달 (Processing & Rendering)

웹 애플리케이션(서버 측) 또는 클라이언트 측 스크립트 엔진이 해당 입력값의 특수 문자(<, >, ", ' 등)를 HTML 엔티티로 치환하지 않은 채 동적 HTML/DOM 구조에 직접 결합하여 출력한다.

3. 브라우저 구문 해석 (Parsing & Execution)

응답을 수신한 희생자의 웹 브라우저는 HTML/DOM 요소를 파싱 하는 과정에서 주입된 악성 문자열을 단순 텍스트 데이터가 아닌 실행 가능한 코드 노드(Script Block 또는 Event Handler)로 인식한다.

4. 동일 출처 정책(SOP) 내 권한 오용

웹 브라우저는 동일 출처 정책(Same-Origin Policy, SOP)에 따라 해당 스크립트가 접속 중인 웹 도메인으로부터 정당하게 수신된 코드로 간주한다. 이에 따라 브라우저는 현재 세션의 Document 객체, 쿠키, 로컬 스토리지 읽기 권한을 스크립트에 부여하고, 해당 사용자의 권한 범위 내에서 비동기 HTTP 요청(AJAX) 등을 수행한다.

XSS 공격으로 발생하는 주요 피해

1. 세션 및 쿠키 탈취 (계정 도용)

로그인 상태를 유지해 주는 중요한 정보(세션 쿠키)를 자바스크립트(document.cookie)로 읽어 들여 공격자의 서버로 빼돌린다. 공격자는 이 쿠키를 이용해 비밀번호 없이도 피해자의 계정으로 즉시 로그인할 수 있다.

2. 사용자 위장 요청

피해자가 로그인되어 있는 상태를 이용해, 피해자 모르게 비밀번호 변경, 게시글 삭제, 돈 이체 등의 요청을 서버로 보낸다.

3. 악성 피싱 사이트 리다이렉트

사용자가 정상적인 웹 사이트에 접속해 있음에도 불구하고, 자바스크립트를 이용해 가짜 로그인 화면이나 악성 파일 다운로드 페이지로 강제 이동시킨다.

4. 웹 화면 변조

웹 페이지의 Form 양식이나 텍스트를 공격자가 원하는 대로 바꾸어 개인정보 입력이나 금융 정보 입력을 유도한다.

XSS 방어 대책

1. 출력 인코딩 (Output Encoding)

사용자의 입력값을 화면에 출력할 때, 브라우저가 코드로 인식할 수 있는 특수문자(<, >, ", ' 등)를 순수한 글자 형태인 HTML 엔티티(&lt;, &gt;, &quot;, &#x27;)로 변환하여 출력한다.

2. HttpOnly 쿠키 설정

중요한 세션 쿠키에 HttpOnly 옵션을 설정하면, 자바스크립트를 통한 쿠키 접근(document.cookie)이 물리적으로 차단되어 XSS가 발생하더라도 쿠키 탈취를 막을 수 있다.

3. 콘텐츠 보안 정책 (CSP, Content Security Policy)

웹 서버가 응답 헤더를 통해 브라우저에게 "허용된 출처의 스크립트만 실행하고, 인라인 스크립트는 실행하지 말 것"을 강제하는 보안 규칙을 적용한다.
